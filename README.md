# Базовая DevOps-инфраструктура в Yandex Cloud

## 1. О проекте

В рамках дипломного проекта я создала простую DevOps-инфраструктуру в облаке Yandex Cloud.

Моя задача заключалась в том, чтобы настроить виртуальную машину, установить на неё Docker, запустить небольшое веб-приложение и автоматизировать его обновление.

Для этого я использовала несколько инструментов:
- **Terraform** — для создания облачной инфраструктуры.
- **Ansible** — для настройки виртуальной машины и установки Docker.
- **Docker** — для запуска приложения в контейнере.
- **Docker Hub** — для хранения собранного Docker-образа.
- **GitHub Actions** — для автоматической сборки и обновления приложения.

В результате получилось приложение, которое работает на виртуальной машине в Yandex Cloud и обновляется автоматически после отправки изменений в GitHub.

## 3. Как устроен проект

Сначала с помощью Terraform я создала виртуальную сеть, подсеть и виртуальную машину в Yandex Cloud.

Затем с помощью Ansible подключилась к серверу и установила Docker.

После этого подготовила небольшое веб-приложение на Python с использованием Flask, создала для него Dockerfile и запустила его в контейнере.

Для автоматизации обновлений настроила GitHub Actions. Теперь при отправке изменений в основную ветку `main` GitHub Actions самостоятельно собирает новый Docker-образ, отправляет его в Docker Hub и обновляет приложение на виртуальной машине.

### Схема работы

```text
Изменения в GitHub
        |
        v
   GitHub Actions
        |
        v
  Сборка Docker-образа
        |
        v
     Docker Hub
        |
        v
  Подключение к серверу
        |
        v
  Обновление контейнера
        |
        v
  Работающее приложение
```

## 5. Создание инфраструктуры

Для создания инфраструктуры я использовала Terraform.

Сначала необходимо скачать репозиторий:

```bash
git clone git@github.com:kumarina-max/terraform-yandex-cloud.git
cd terraform-yandex-cloud
```

Затем выполнить инициализацию Terraform:

```bash
terraform init
```

Проверить конфигурацию:

```bash
terraform fmt
terraform validate
```

Посмотреть, какие ресурсы будут созданы:

```bash
terraform plan
```

Создать инфраструктуру:

```bash
terraform apply
```

После создания виртуальной машины можно посмотреть её публичный IP-адрес:

```bash
terraform output -raw vm_public_ip
```

Для работы Terraform используется S3-совместимое хранилище Yandex Object Storage, в котором сохраняется состояние инфраструктуры. Это позволяет сохранять информацию о созданных ресурсах между запусками Terraform.

## 6. Настройка сервера через Ansible

После создания виртуальной машины я использовала Ansible для установки Docker.

Скачать репозиторий:

```bash
git clone git@github.com:kumarina-max/ansible-yandex-cloud.git
cd ansible-yandex-cloud
```

В файле `inventory/hosts.ini` указан адрес виртуальной машины. Если после пересоздания инфраструктуры IP изменился, его необходимо обновить.

Сначала проверяем подключение к серверу:

```bash
ansible -i inventory/hosts.ini web -m ping
```

Если подключение работает, запускаем установку Docker:

```bash
ansible-playbook -i inventory/hosts.ini playbooks/install-docker.yml
```

После установки можно проверить версии Docker:

```bash
docker --version
docker compose version
```

## 7. Запуск приложения через Docker

В качестве примера я создала небольшое веб-приложение на Python и Flask.

Оно отображает страницу с информацией о проекте и имеет отдельный адрес для проверки состояния приложения — `/health`.

Исходный код находится в репозитории:

[Docker App Yandex Cloud](https://github.com/kumarina-max/docker-app-yandex-cloud)

Для локальной сборки и запуска приложения используется команда:

```bash
docker compose up -d --build
```

Проверить, что контейнер запущен:

```bash
docker ps
```

Открыть приложение:

```text
http://localhost:8081
```

Проверить его состояние:

```text
http://localhost:8081/health
```

Ожидаемый ответ:

```json
{"status":"healthy"}
```

## 8. Хранение Docker-образа

После сборки приложения Docker-образ отправляется в Docker Hub.

Название образа:

```text
kumarina/docker-app-yandex-cloud:latest
```

При необходимости собрать и отправить образ вручную можно следующими командами:

```bash
docker build -t kumarina/docker-app-yandex-cloud:latest .
docker push kumarina/docker-app-yandex-cloud:latest
```

## 9. Автоматическое обновление приложения (GitHub Actions)

Для автоматизации я настроила GitHub Actions.

Файл с настройками находится в репозитории приложения:

```text
.github/workflows/deploy.yml
```

После отправки изменений в ветку `main` автоматически выполняются следующие действия:

1. GitHub получает последние изменения из репозитория.
2. Собирается новый Docker-образ.
3. Образ отправляется в Docker Hub.
4. GitHub Actions подключается к виртуальной машине по SSH.
5. Старый контейнер заменяется новым.
6. Приложение снова запускается на сервере.

Для подключения используются GitHub Secrets. В них сохранены данные для входа в Docker Hub и подключения к виртуальной машине. Сами секретные значения в исходном коде не хранятся.

## 10. Проверка работы приложения

После развёртывания приложение доступно по публичному IP-адресу виртуальной машины:

```text
http://<PUBLIC_IP>:8081
```

Для проверки состояния приложения используется адрес:

```text
http://<PUBLIC_IP>:8081/health
```

На виртуальной машине также можно проверить работающий контейнер:

```bash
docker ps
```

Посмотреть логи приложения:

```bash
docker logs devops-diploma-app
```

Во время первоначального развёртывания я проверила доступность главной страницы и получила успешный ответ от `/health`.

## 11. Удаление и повторное создание инфраструктуры

Для проверки того, что инфраструктуру можно создавать и удалять с помощью Terraform, необходимо выполнить:

```bash
terraform destroy
```

После подтверждения Terraform удалит созданные им ресурсы: виртуальную машину, подсеть и виртуальную сеть.

Бакет Object Storage с Terraform state создавался отдельно, поэтому его нужно сохранить.

Для повторного создания инфраструктуры используется команда:

```bash
terraform apply
```

После повторного создания необходимо:

1. Получить новый публичный IP виртуальной машины.
2. Обновить IP в Ansible inventory.
3. Повторно запустить Ansible playbook для установки Docker.
4. Обновить `DEPLOY_HOST` в GitHub Secrets, если IP изменился.
5. Запустить GitHub Actions, чтобы приложение снова развернулось на сервере.
6. Проверить главную страницу и адрес `/health`.

Этот этап позволит убедиться, что инфраструктуру можно повторно развернуть, не настраивая всё вручную.
